# MISE 1.1.20 コードレビュー／未解決課題

更新日：2026-09-02  
対象：MISE 1.1.20ソース  
方針：修正済みの問題は本資料から除外し、現在も残る問題と実装中に新しく判明した問題だけを管理する。

## P1：主要機能・出力品質

| ID | 未解決内容 | 完了条件 |
|---|---|---|
| R-04 | PDF／AIの画像抽出は、元ページ画像の上へ単色マスクと抽出画像を置く近似方式。写真、グラデーション、透明、重なりでは移動・削除跡を完全復元できない | PDFコンテンツを再構成するか、近似編集レイヤーとしてデータ構造とUIを明確に分離する |
| R-05 | PDF／AI文字編集も単色マスク方式で、回転・縁取り・字間・透明・背景模様を完全に消去できない | 原本文字の除去を保証できる形式だけ編集可能にし、それ以外は固定外観として扱う |
| R-06 | 複数選択には共通の外接選択枠がなく、拡大縮小・回転はアクティブ要素だけに作用する | 共通枠、基準点、倍率、回転を一元管理し、混在選択を一操作で変形できる |
| R-09 | PDF／AI原本切れは警告できるが、参照先を直す再リンク画面と原本ハッシュ照合がない | 再リンク、ページ照合、ハッシュ確認、高精細再描画を一つの導線で行える |
| R-11 | PDF出力はページ全体を画像として貼る高精細ラスターPDFで、文字・図形・QRをベクター保持しない | 出力方式を画面に明示し、ベクターPDF経路を追加する |

## P2：操作・連動性

| ID | 未解決内容 | 完了条件 |
|---|---|---|
| R-12 | 一部の文字・図形・QRプロパティは、値が変わらなくてもUndo履歴とDirty状態を作る | 全属性更新を変更差分のある時だけ実行する共通コマンドへ統合する |
| R-13 | タイト文字の最小3ptは実装済みだが、数値入力と各ハンドルで最小値到達時のアンカー規則が完全には共通化されていない | 幅・高さ入力、四隅・四辺ハンドルを同一の文字変形ポリシーへ統合する |
| R-14 | 回転・傾斜・縁取り・立体効果を含む見た目の外接範囲が、整列・スナップ・安全領域検査へ反映されない | 共通`VisualBounds`を導入し、選択・整列・検証で共有する |
| R-15 | 画像トリミング時の「フレーム維持」と「被写体実寸維持」が選べず、経路により物理サイズの扱いが異なる | トリミング規則を選択可能にし、差し替え・自動・手動で同じ計算を使う |
| R-16 | タイト文字では実質左上配置なのに、中央・右・上下揃えのモデル値とUIが残る | タイト文字では無効化するか、フレーム内配置として実装する |
| R-17 | 線の矢印先端、太い枠線、立体効果が選択枠・安全領域・重なり検査からはみ出す | 効果を含む外接範囲を計算する |
| R-18 | PDF／AI編集読込は文字と一部PNG/JPEG画像のみで、アウトライン、ベクターパス、クリップ、透明、ブレンド、グループを編集できない | 読込結果の種類・件数・非対応理由を表示し、対応形式を段階的に拡張する |
| R-19 | PDF互換情報を持たないAIファイルは直接読み込めない | IllustratorでPDF互換保存する案内、画像化、取消を選択できるエラー導線を用意する |
| R-21 | Undo/Redoはプロジェクト全体のJSONスナップショット方式で、大規模データのメモリ使用量が大きい | 差分コマンド履歴と容量上限を導入する |
| R-22 | ガイド等の文書設定と表示設定が混在し、一部変更をUndoできない | 文書設定とビュー設定を分類し、保存対象の変更をUndoへ統一する |
| R-23 | ラスターPDF化後の最小線幅・最小文字・QRの実ピクセル検査がない | 出力DPIごとの最終画像検査を追加する |
| R-24 | 自動保存に元ファイルパス・最終保存時刻・変更数がなく、通常保存版との差が分かりにくい | 最近使用一覧で元ファイルと差分状態を表示する |

## P3：保守性・診断

| ID | 未解決内容 | 完了条件 |
|---|---|---|
| R-25 | `MainWindow.cs`へUI、編集、描画、読込、保存、印刷、履歴が集中している | 編集コマンド、選択変形、文書サービス、レンダラーへ段階的に分割する |
| R-26 | 全面`RebuildCanvas()`と部分`RefreshTextVisual()`が併存し、フォーカスや選択維持の規則が分散している | 更新種別をモデル・レイアウト・描画へ整理する |
| R-27 | 例外を握りつぶす経路があり、画像・フォント・印刷の品質低下を判別しづらい | 回復可能エラー、品質警告、ログIDを統一表示する |
| R-29 | `Brightness`、`Contrast`、`Saturation`がモデルにあるがUI・描画・出力へ接続されていない | 機能実装するか保存モデルから削除する |
| R-30 | ロック、保存移行、面付けDPI、Undo、PDF／AI各モードの自動回帰テストが不足している | Windows CIへ機能別テストを追加する |
| R-31 | 面付け描画は指定DPIへ修正したが、処理全体はUIスレッド上の同期描画で、高DPI・多ページ時に操作不能時間が生じ得る | キャンセル可能なバックグラウンド処理と二重起動防止を実装する |

2. R-12・R-13：属性変更・文字変形・Undoの統一
3. R-04・R-05・R-18・R-19：PDF／AI編集読込の設計分離
4. R-14・R-17・R-23：実描画境界と最終出力検査
5. R-09・R-21・R-22・R-24・R-31：再リンク、履歴、自動保存、非同期出力

新しい問題を確認した場合はこの版へ追記し、修正完了時は該当項目を削除して次版を作成する。
